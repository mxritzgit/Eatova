Reviewed `design/app-icon-polish` at `4ae47eb`, including the existing local
design work. Ten subagents ran concurrently across auth, sync/cache, Coach,
Food/search, recipes, health/notifications, UI, Edge Functions, PostgreSQL,
and maintenance/platform code. The commander checked findings, controlled
ownership, requested counterexamples, and integrated reviewed changes.

Each agent worked in its own detached worktree containing the exact design
baseline. Original files and hashes are preserved under ignored
`.agents/review-2026-09-08/`. No tests modified the shared production tree.
This report records verification before delivery. Implementation commit
`919a55c` is now tracked in [PR #68](https://github.com/mxritzgit/Eatova/pull/68);
GitHub is authoritative for its current CI and merge status. The user
authorized merge only after green CI. Migration deployment, Edge Function
deployment and new device installation remain separate delivery steps.

## Deliberate boundaries and delivery

- Android has no step provider. The Steps card still hides when data is null;
  no unavailable-state feature was selected or added.
- Existing shoe-print/conversation icons, responsive design work, theme tokens,
  calorie model, confirmation-before-recipe-save, device-only images, encrypted
  cache fallbacks and per-operation outbox durability are retained.
- OFF's legacy search fallback has no equivalent full-text replacement in its
  product v2/v3 endpoints; no unsupported API migration was made. See the
  [official API reference](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/ref-cheatsheet/).
- Recovery Back after valid OTP still leaves an authenticated session. Mailbox
  ownership is established; mandatory password completion is a product-flow
  decision, not a newly proven authentication bypass. It was not changed.
- The existing stats deduplication tradeoff remains: if a booked bundle loses
  its response while another bundle is created, merging both under the first
  request ID can omit the newer lifetime counters. Actual meal/weight records
  survive. This is documented in `home_store_sync.dart`, predates this review
  (`2c8e4c42`, `8cc6ef11`), and is reflected in `fixlauf_a_timeout_test.dart`.
  S1 repairs lost in-flight delivery at logout; it does not replace that
  single-bundle model with separately persisted immutable bundles.
- No broad feature removal, speculative dependency bump, privacy-gate change,
  or production-setting change was justified by this bounded review.
- Account mutations remain native-only. Web is rejected because GoTrue's web
  broadcast channel would bypass the isolated client's adoption guard.
- Apply `20260908120000_chat_quota_refund_day.sql` **before** deploying updated
  `coach-chat`. Older handlers retain their legacy RPC during staged rollout;
  the midnight fix becomes live only after both steps.
- Native speech uses [Apple's current microphone permission API](https://developer.apple.com/documentation/avfaudio/avaudioapplication/requestrecordpermission(completionhandler:))
  where available. An iOS build and real microphone/permission test remain
  separate from the passing Dart lifecycle tests.
- Real authenticated mail, provider and device flows were not exercised against
  production. This review is not a blanket security clearance.
